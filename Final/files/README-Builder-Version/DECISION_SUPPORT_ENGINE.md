# Decision Support Engine

## SHAP → Recommendation Conversion

```
Negative SHAP Factor (e.g. "Nitrogen Content" = -0.15)
      │
      ▼
Category lookup (RECOMMENDATION_CATEGORY: feature → agronomic category, e.g. "nitrogen")
      │
      ▼
Level determination (_level(): is the farmer's actual value "low" or "high"
                      relative to the real training-data median for this crop?)
      │
      ▼
Deterministic action lookup (RECOMMENDATIONS[category][level], e.g.
                              "Apply nitrogen fertilizer in split doses")
      │
      ▼
{"issue": "Nitrogen availability", "action": "...", "reason": "..."}
```

## Why Deterministic Rules, Not SLM-Generated Recommendations

The recommendation *actions* are generated by fixed, auditable rules
(`RECOMMENDATIONS` dict in `model_service.py`), never invented by the SLM.
The SLM's role (see `SLM_INTEGRATION.md`) is strictly to phrase these
already-vetted recommendations naturally and in the farmer's language —
never to generate new ones. This is a deliberate safety boundary: a wrong
agronomic recommendation from a hallucinating language model could cause
real harm to a farmer's crop, so recommendation logic stays in
deterministic, reviewable Python code, not model output.

## Level Determination Logic

For each simulatable feature, `_level(feature, value, ref_stats)` compares
the farmer's actual input value against that crop's median value in the
real training data:
- Value ≤ median → `"low"` recommendation variant (e.g. "apply more
  fertilizer")
- Value > median → `"high"` recommendation variant where one exists (e.g.
  "reduce pesticide use"), otherwise falls back to the `"low"` variant

## Expected Impact

Recommendation *actions* do not themselves carry a numeric expected-impact
estimate — that's what the separate What-If Simulation Engine computes
(see `WHAT_IF_SIMULATION_ENGINE.md`), by actually applying a realistic
adjusted value for each simulatable negative factor and re-running the
trained model, rather than a hardcoded "+X% if you do this" claim attached
to the recommendation text itself.

## Multilingual Recommendations

Every recommendation action has a translated variant in
`RECOMMENDATIONS_I18N` (Tamil, Hindi), keyed by the same category/level
structure as the English `RECOMMENDATIONS` dict, with a tested fallback
(`get_translated()` falls back to the `"low"` variant if a `"high"`
translation is missing, then to English if the language itself is
missing) — see `TRANSLATION_WORKFLOW.md`.
